## 2026-08-25 — Task 1.1 hardened XML loader + detection

- **D-024 XML DOM/XPath stack in core = `@xmldom/xmldom` 0.9.12 + `xpath` 0.0.34 (+ `zod` 4.4.3 for the T1 `format` schema).** Pure JS, versions per D-006. Hardening is parser-independent and runs on the raw text *before* any parser: size cap (20 MiB), **any `<!DOCTYPE` is rejected outright** (no DTD ⇒ no external entities, no billion laughs — regardless of which engine later re-parses the same text: Saxon-JS, xmllint-wasm), nesting-depth scan (256), then xmldom with `onError` → `XmlLoadError{code,line,column}`. Error codes `KONTOR-XML-{SIZE,DTD,DEPTH,MALFORMED}`. Saxon-JS was considered as sole parser+XPath (it is a runtime dep anyway) but rejected for the loader: weaker well-formedness diagnostics (no line/col) and heavier parse; it still re-parses `XmlDocument.text` for the transform.
- **D-025 `DetectedFormat` facets:** `profile` is a CII/ZUGFeRD-only concept — the bare `urn:cen.eu:en16931:2017` maps to `profile:"en16931"` for CII, `null` for UBL. The XRECHNUNG ZUGFeRD profile cannot be told apart from a plain XRechnung CII by the guideline ID; it is asserted from the PDF's XMP `fx:ConformanceLevel` (Task 1.2). XRechnung version + variant (`base|extension|cvd`) come from the CustomizationID using the same string keys as KoSIT `scenarios.xml` (D-017).
- **D-026 PDF extraction (Task 1.2) uses `pdf-lib` 1.17.1 low-level objects** (catalog `/Names/EmbeddedFiles` name tree + `/AF`, `PDFRawStream`), i.e. the same library as generation (D-022) — no second PDF parser. FlateDecode attachments are inflated with Node `zlib.inflateSync({ maxOutputLength })` so a decompression bomb is rejected before it materialises (`KONTOR-PDF-DECOMPRESS-SIZE`); other filters use pdf-lib's decoders behind a raw-size check. Encrypted PDFs are rejected (`KONTOR-PDF-ENCRYPTED`; detected by message as well as `instanceof`, because pdf-lib's CJS/ESM builds ship distinct class identities). Attachment choice: `factur-x.xml` > `zugferd-invoice.xml` > `xrechnung.xml`, else first embedded file whose bytes are XML with a CII/UBL root. The XMP `fx:ConformanceLevel` is authoritative for the ZUGFeRD profile (it is the only way to see the XRECHNUNG profile).
- **D-027 `InvoiceModel` is a plain typed object; the PRD §5.3 `{bt, value}` shape is an output projection.** Zod (`InvoiceModelSchema`) is the single source of truth and the TS type is inferred from it. A static path→BT/BG table (`model/bt-map.ts`) drives `toAnnotatedJson()` and the generated `docs/BT-COVERAGE.md` (`pnpm bt-coverage`, 164/164 core BTs mapped). Rationale: plausibility math and generation are far simpler on unwrapped fields; the annotated shape is only needed at the tool boundary. Amounts/quantities/percentages stay verbatim strings (decimal.js downstream). Parsers are data tables (`parse/ubl.ts`, `parse/cii.ts`) run by one generic XPath extractor; missing mandatory fields become `KONTOR-PARSE-MISSING` warnings instead of exceptions.

## 2026-08-25 — Task 1.4 validation pipeline

- **D-028 Runtime artifacts are committed, gzipped, in `packages/rules/artifacts/`** (`pnpm rules:build`, `tools/build-rules-artifacts.ts`): the four SEFs (`*.sef.json.gz`, 20 MB → 0.5 MB), the XSD subset the scenarios reference (UBL 2.1 Invoice + CreditNote + `common/`, CII D16B), `scenarios.json` (typed projection of KoSIT `scenarios.xml`, D-017) and `MANIFEST.json` with sha256 of every file and the D-019 patch note. Loaded lazily and cached by `@kontor-mcp/rules` (`loadSef`, `loadXsdSet`, `loadScenarios`). Rationale: `npx @kontor-mcp/server` must work without a build step (D-018) and without Java; gzip keeps the npm tarball and git history small.
- **D-029 KoSIT parity rules implemented in `core/src/validate`:** scenario = exact (syntax, CustomizationID) match; SVRL `flag` fatal→error, warning→warning, information→info; `customLevel` overrides applied per scenario; verdict = *no error-level finding*; XSD failure (`ruleId "XSD"`, severity `fatal`) skips the Schematron layer as the KoSIT validator does; unmatched documents get XSD-only validation plus an informational `KONTOR-SCENARIO-NONE` (ZUGFeRD profiles below EN 16931 are refined in Phase 2). Layer 1 = `xmllint-wasm` 5.3.0 (libxml2 2.13 in WASM, worker thread, ~60 ms warm); layer 2 = Saxon-JS 2.7 (`saxon-js` ships no typings → `core/src/types/saxon-js.d.ts`). Saxon `Q{ns}local` locations are normalised to prefixed XPath. Result: verdict parity 89/89 with the oracle over spike + full official suite; `pnpm oracle --diff` now drives the core engine (the spike engine `tools/spike-saxon.ts` was retired) and compares rule id *and* level. CI fetches the pinned artifacts (cached by manifest hash) so the conformance test runs on every push.
